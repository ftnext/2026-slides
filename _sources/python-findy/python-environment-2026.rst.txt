Python処理系を取り揃える
------------------------------------------------------------

`major(3).minor(15).micro(2) <https://devguide.python.org/developer-workflow/development-cycle/index.html>`__

* minorごとにインストール（現在 `Active <https://www.python.org/downloads/>`__ な3.15〜3.11から使うものを）
* micro（バグ修正）が上がっていたら再度インストールして、コマンド自体を置き換え [#python3-command]_

.. [#python3-command] ``python3`` コマンドは最後にインストールしたminorバージョンに向きます。区別のために ``python3.15`` とminorまで指定したい派です

minorバージョンアップ例：3.10の ``match``
------------------------------------------------------------

* 言語機能が追加されるが、古い書き方も有効
* `Structural Pattern Matching <https://docs.python.org/ja/3/whatsnew/3.10.html#pep-634-structural-pattern-matching>`__ は3.9のサポートが終了した2025年10月以降本格的に使うように

.. https://peps.python.org/pep-0596/
    As of 2025-10-31, 3.9 has reached the end-of-life phase of its release cycle.

.. code-block:: python

    def fizzbuzz(number):
        match number % 3, number % 5:
            case 0, 0: return "FizzBuzz"
            case 0, _: return "Fizz"
            case _, 0: return "Buzz"
            case _, _: return str(number)

.. https://gihyo.jp/news/report/01/pyconjp2021/0002#sec1

venvモジュール
------------------------------------------------------------

* Python処理系にバンドルされる標準ライブラリの1つ
* https://docs.python.org/ja/3/library/venv.html
* *仮想環境* を作る（主にCLIで使う）

仮想環境を **有効化**
------------------------------------------------------------

.. code-block:: console
    :caption: Windows

    > .venv\Scripts\activate

.. code-block:: console
    :caption: macOS または Linux

    % source .venv/bin/activate

* :command:`python` コマンドに揃う
* ``deactivate`` で抜けます

Pythonのサードパーティパッケージ
------------------------------------------------------------

* **PyPI** （Python Package Index）がデフォルト

    * https://pypi.org/

* GitHub等で公開も可能

サードパーティパッケージのインストール [#why-httpx2]_
------------------------------------------------------------

``(.venv)`` は仮想環境が有効（``PATH`` などが変更済み）なことを示します

.. code-block:: console
    :caption: `12. 仮想環境とパッケージ`_

    (.venv) $ python -m pip install httpx2

.. [#why-httpx2] インストールしているのは、注目のHTTPクライアントです。https://github.com/pydantic/httpx2

pip
------------------------------------------------------------

* **パッケージマネージャ** のCLI（ただし機能は *弱い*）
* https://pip.pypa.io/en/stable/
* サードパーティパッケージだが、Python処理系に *バンドル* されている [#stdlib-ensurepip]_
* venvはpipをインストールした仮想環境を作る

.. [#stdlib-ensurepip] 標準ライブラリの `ensurepip <https://docs.python.org/ja/3/library/ensurepip.html>`__ によります。拙ブログの `仕組み読み解き <https://nikkie-ftnext.hatenablog.com/entry/python-stdlib-ensurepip-run-pip-install-pip>`__

例：既存のPythonプロジェクトの開発に合流
------------------------------------------------------------

.. code-block:: console
    :caption: 仮想環境を作って依存をインストールして始める

    % git clone https://github.com/my-company/awesome-project.git
    % cd awesome-project
    % python3.15 -m venv .venv --upgrade-deps
    % source .venv/bin/activate
    (.venv) % python -m pip install -e '.[dev]'

:file:`.venv/bin/python`
------------------------------------------------------------

* :file:`.venv/bin/activate` は環境変数 ``PATH`` を更新して、:file:`.venv/bin/python` が見つかるようにしている
* 実は有効化せずに :file:`.venv/bin/python` を **直接実行** してもよい

⚠️仮想環境ってrenameすると壊れます
------------------------------------------------------------

.. code-block:: console

    % mv .venv myenv
    % myenv/bin/kojo-day kokoro
    zsh: myenv/bin/kojo-day: bad interpreter: /.../.venv/bin/python: no such file or directory

仮想環境は **使い捨て** （disposable）
------------------------------------------------------------

* インストールされたパッケージ一覧を書き出す
* 新しい名前の仮想環境に再度インストール

.. code-block:: console

    % .venv/bin/python -m pip freeze > requirements.txt
    % python3.15 -m venv myenv --upgrade-deps
    % myenv/bin/python -m pip install -r requirements.txt

:command:`uv sync` お試しあれ
============================================================

* :file:`pyproject.toml` があれば（:file:`uv.lock` なくとも）うまくいくことが多い
* ツールによらず使える、Pythonプロジェクトのメタデータを書くファイルです（`PEP 518 <https://peps.python.org/pep-0518/>`__）

``uv sync`` の裏で
------------------------------------------------------------

* Pythonを見つける（ない場合はダウンロード）
* ロックファイル :file:`uv.lock` 作成
* 仮想環境 :file:`.venv/` を作り、ロックファイルと同期

落ち穂拾い：uvと仮想環境
============================================================

* venvは使わずに仮想環境（ディレクトリ）を作る [#pep-405]_
* pipはない（uvが担えるので）
* uvコマンドを使う限りは **仮想環境は意識しなくてよくなっている**

.. [#pep-405] `PEP 405 – Python Virtual Environments <https://peps.python.org/pep-0405/>`__

uvと仮想環境 続き
------------------------------------------------------------

* 使う中で仮想環境をおかしくしてしまったら :file:`.venv/` を消してみる（``uv sync`` ですぐ復活。disposable）
* uvの作った仮想環境を直接触りたくなったら `uv venv <https://docs.astral.sh/uv/reference/cli/#uv-venv>`__ や `uv pip <https://docs.astral.sh/uv/reference/cli/#uv-pip>`__ コマンド

仮想環境との同期
------------------------------------------------------------

* ロックファイルと仮想環境を最新化できる（`Locking and syncing <https://docs.astral.sh/uv/concepts/projects/sync/>`__） [#locked-option]_
* `--frozen`: ロックファイルが最新でなくてもそのまま使って同期（CIで指定）
* `--no-sync`: 仮想環境を最新化せず

.. [#locked-option] `--locked`: ロックファイルが最新でないならエラー

裏の仕組み：python-build-standalone

* https://github.com/astral-sh/python-build-standalone
* **Python処理系をダウンロードしたら動かせる** ようになっている！uvはこれを使っている

LiteLLM [#litellm-nikkie-article]_
------------------------------------------------------------

.. code-block:: python

    from litellm import completion

    for model in ["openai/gpt-6.1-luna", "gemini/gemini-3.8-flash"]:

LiteLLMへの攻撃で状況は大きく変わった
------------------------------------------------------------

* LiteLLM `1.82.7と1.82.8 <https://docs.litellm.ai/blog/security-update-march-2026>`__ （当時最新版）に悪意あるコードが仕込まれていた [#litellm-compromised-again]_
* 最新版インストール後、importしただけで環境の秘密情報が抜かれる（uvxして踏みました）
* **最新版のインストールがリスク**

.. 邪悪なlitellm_init.pth https://nikkie-ftnext.hatenablog.com/entry/cope-with-compromised-litellm-1.82.8-with-gpt-5.4

.. [#litellm-compromised-again] `2026年10月にも1.107.0で再度侵害 <https://docs.litellm.ai/blog/security-incident-oct-21-2026-attack-chain>`__ されてしまいました  

「最新版には悪意あるコードが入っているかも」
------------------------------------------------------------

* ロックファイルがあるPythonプロジェクトなら最新版は取りに行かない（踏むリスク低）
* 古いプロジェクトや、``uvx`` ・inline script metadata [#uv-lock-inline-script-metadata]_ といった使い方で *ロックファイルを作っていない*

.. [#uv-lock-inline-script-metadata] `uv lock --script <https://docs.astral.sh/uv/reference/cli/#uv-lock--script>`__ はあります

ロックファイルがない状況で最新版のリスクを減らす
----------------------------------------------------------------------

* cooldownの設定
* セキュアなインデックスへの切り替え

完璧な1つの対策はない。どの対策にも穴があるが **重ね合わせて** 貫通しなくする🧀 [#swiss-cheese-model]_

.. [#swiss-cheese-model] `スイスチーズモデル <https://ja.wikipedia.org/wiki/%E3%82%B9%E3%82%A4%E3%82%B9%E3%83%81%E3%83%BC%E3%82%BA%E3%83%A2%E3%83%87%E3%83%AB>`__

cooldown
------------------------------------------------------------

最新版を一定期間避ける設定。コミュニティが攻撃を検出し、隔離・削除

.. code-block:: toml
   :caption: :file:`~/.config/uv/uv.toml` [#uv-exclude-newer]_

   exclude-newer = "7 days"

.. https://nikkie-ftnext.hatenablog.com/entry/python-package-installer-how-to-cooldown-after-compromised-litellm

.. [#uv-exclude-newer] 出た直後のバグフィックスを当てるために `--exclude-newer-package=foobar=false <https://docs.astral.sh/uv/reference/cli/#uv-run--exclude-newer-package>`__

2-2. eMudhra証明書の事故
============================================================

* https://emudhra.we-have-a-problem.com/
* 中間認証局eMudhraが管理する秘密鍵（8つ）が公開鍵から容易に復元できてしまった
* 誰でもなりすませる！（HTTP **S** 通信にリスク😱）

対応いただいているOSS各位に深く感謝申し上げます

eMudhra証明書を含むチェーンを信頼してはいけません
------------------------------------------------------------

* パッケージがバンドルする証明書から各所で削除が進む
* Pythonまとめ `Information for Python users regarding eMudhra / emSign CA certificate security incident <https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576>`__
* `certifi <https://github.com/certifi/python-certifi>`__ を **2026.10.19** 以上へ [#pip-certifi-update]_

.. [#pip-certifi-update] certifiをvendorする **pipは26.2.2以上** へ

uvでの対応
------------------------------------------------------------

* uv **0.13.4** でバンドルした証明書を更新（webpki-root-certs 1.0.10）
* Pythonのダウンロードや、PyPIからパッケージのインストールの通信に使う

.. UV_SYSTEM_CERTS=true

Pythonでの対応
------------------------------------------------------------

* Python 3.15.2, 3.14.10, 3.13.18, 3.12.16, 3.11.18
* 標準モジュール **ssl** がeMudhraの証明書を含むチェーンを **ブロック** するようにCVE対応した
* :command:`uv python upgrade` (uv 0.13.6以上)

macOSはeMudhraの証明書が残っている [#apple-support-emduhra]_
----------------------------------------------------------------------

* eMudhraの証明書は信頼できないという情報はマシンに配信されている（Safariやメールに適用）
* しかし :file:`/etc/ssl/cert.pem` に残る（Appleのアップデート待ち）
* 一般ユーザは安全、 **開発者は注意が必要**

.. [#apple-support-emduhra] Apple Support `About the compromised eMudhra intermediate CAs <https://support.apple.com/en-us/149555>`__

**macOSとuvの組合せ** がややこしや
------------------------------------------------------------

* uvが使うpython-build-standaloneは :file:`/etc/ssl/cert.pem` を見てしまう挙動 [#blog-macos-cert-experiments]_
* Python 3.15.2以降でsslモジュールがブロックするのでだいぶ安全になった

.. [#blog-macos-cert-experiments] 拙ブログ `uvが管理するPythonを3.14.10に更新することで、macOSでurllib・urllib3・aiohttp・niquestsはeMudhraの問題の証明書チェーンを受け入れなくなる！ <https://nikkie-ftnext.hatenablog.com/entry/we-wait-macos-cacert-update-uv-python-build-standalone-but-python-fix-ssl-cve>`__
