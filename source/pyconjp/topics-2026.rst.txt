.. [#how-uv-got-so-fast] 他に `How uv got so fast <https://nesbitt.io/2025/12/26/how-uv-got-so-fast.html>`__

uvがコーディングエージェントにベスト？
------------------------------------------------------------

* コーディングエージェントは一般に書き込めるディレクトリの制限がある
* ``uv run`` が（書き込めるディレクトリとは別の）キャッシュを積極利用するために、 *余計な設定* が必要
* GPT-5.6 Solは ``uv run`` でキャッシュに書き込めないとき、``UV_CACHE_DIR`` 指定で :file:`/tmp` 下に回避している様子を見る

uvのキャッシュを考慮してコーディングエージェントを設定
------------------------------------------------------------

.. code-block:: toml
    :caption: Codexの例（:file:`.codex/config.toml`）

    [sandbox_workspace_write]
    writable_roots = [
        "/Users/nikkie/.cache/uv",
    ]

* コーディングエージェントには ``uv run pytest`` を渡さず、 **.venv/bin/pytest** [#adk-python-agents-md]_

2.セキュリティ：変わり始めたPythonの世界
============================================================

* 近年npmでサプライチェーン攻撃が展開されている（IMO：攻撃者を強く非難します）
* PyPIでも2026年3月、LiteLLMでサプライチェーン攻撃が発生

LiteLLM [#litellm-nikkie-article]_
------------------------------------------------------------

.. code-block:: python

    from litellm import completion

    for model in ["openai/gpt-5.6-luna", "gemini/gemini-3.7-flash"]:
        response = completion(model=model, messages=messages)
        print(response.choices[0].message.content)

.. [#litellm-nikkie-article] 拙ブログ：`LiteLLMを使って、同じプロンプトを複数のLLMのWeb APIに送る（GPTとGeminiを例に） <https://nikkie-ftnext.hatenablog.com/entry/call-gpt-and-gemini-web-apis-with-litellm-awesome>`__

LiteLLMへの攻撃で状況は大きく変わった
------------------------------------------------------------

* LiteLLMの最新版に悪意あるコードが仕込まれていた
* 最新版インストール後、importしただけで環境の秘密情報が抜かれる（uvxして踏みました）
* **最新版のインストールがリスク**

.. 邪悪なlitellm_init.pth https://nikkie-ftnext.hatenablog.com/entry/cope-with-compromised-litellm-1.82.8-with-gpt-5.4

「最新版には悪意あるコードが入っているかも」
------------------------------------------------------------

* ロックファイルがあるPythonプロジェクトなら最新版を取りに行かないのでリスクは低い
* 古いプロジェクトや、``uvx`` ・inline script metadata [#uv-lock-inline-script-metadata]_ にはロックファイルはない

.. [#uv-lock-inline-script-metadata] `uv lock --script <https://docs.astral.sh/uv/reference/cli/#uv-lock--script>`__ はあります

ロックファイルがない状況で最新版インストールのリスクを減らすには
----------------------------------------------------------------------

* cooldownの設定
* セキュアなインデックスへの切り替え

完璧な1つの対策はない。どの対策にも穴があるが重ね合わせて貫通しなくする🧀

.. スイスチーズモデル

cooldown
------------------------------------------------------------

最新版を一定期間避ける設定。コミュニティが攻撃を検出し、隔離・削除

.. code-block:: toml
   :caption: :file:`~/.config/uv/uv.toml`

   exclude-newer = "7 days"

.. code-block:: toml
   :caption: :file:`~/.config/pip/pip.conf` （ただしpip>=26.1）

    [global]
    uploaded-prior-to=P3D

.. https://nikkie-ftnext.hatenablog.com/entry/python-package-installer-how-to-cooldown-after-compromised-litellm

セキュアなインデックス
------------------------------------------------------------

* 例：`Takumi Guard <https://shisho.dev/docs/ja/r/202603-takumi-guard-pypi/>`__ （無料）
* 新規開発が止まっているようなプロジェクトで採用
* ロックファイルはなく、pipが古くてcooldownも効かないが、`PIP_INDEX_URL <https://pip.pypa.io/en/stable/cli/pip_install/#cmdoption-i>`__ 指定だけで済んで作業効果は高い

サプライチェーン攻撃のリスクを認識しましょう
------------------------------------------------------------

* 私は、``uvx`` から ``uv tool install`` に切り替えました（最新版にアクセスする回数を減らす）
* 今すぐ **cooldown** を設定しましょう！
* 提言：Python書籍（特に入門書）で最新版を入れる記載をしているのも危ないと思います（cooldownを案内しては）
