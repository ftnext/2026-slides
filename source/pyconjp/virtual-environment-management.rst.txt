人力仮想環境管理を指南 [#we-are-package-manager]_
============================================================

.. code-block:: bash
    :caption: `12.3. pip を使ったパッケージ管理 <https://docs.python.org/ja/3/tutorial/venv.html#managing-packages-with-pip>`__ [#why-python-m]_

    $ python -m venv .venv --upgrade-deps
    $ source .venv/bin/activate
    (.venv) $ python -m pip install httpx2
    (.venv) $ python -m pip freeze > requirements.txt
    (.venv) $ python -m pip uninstall httpx2

人力管理はしんどくなる
------------------------------------------------------------

* ``pip freeze`` は仮想環境内のパッケージをファイルに書き出している [#virtual-environment-disposable]_
* そもそも **順番が逆** では？ [#pip-tools-compile]_
* ``pip uninstall`` は `単体アンインストール <https://nikkie-ftnext.hatenablog.com/entry/python-dependency-management-pip-only-uninstall-implementation>`__ なので、使っていないパッケージが残ることも

.. [#virtual-environment-disposable] ``pip freeze`` の出力はそっくりそのまま再現するためのものだと捉えています（公式チュートリアルに仮想環境はdisposableとあります）

.. [#pip-tools-compile] `pip-tools <https://pip-tools.readthedocs.io/en/stable/>`__ の ``pip-compile``

Poetry（2018〜） [#pycon-apac-2023-peacock]_
------------------------------------------------------------

.. https://python-poetry.org/docs/#installation

.. code-block:: shell

    $ pipx install poetry

.. [#pycon-apac-2023-peacock] 当時は画期的だったが、「`Comparison of Packaging Tools in 2023 <https://2023-apac.pycon.jp/timetable?id=XEGZUD>`__」にて近年の標準からの遅れの指摘。2025年の `v2.0.0 <https://github.com/python-poetry/poetry/releases/tag/2.0.0>`__ で待望の ``[project]`` サポート

.. code-block:: shell
    :caption: `基本的な使い方 <https://python-poetry.org/docs/basic-usage/>`__

    $ poetry new my-project
    $ cd my-project
    $ poetry add 'httpx2>=2.12.0'  # poetry.lock 作成
    $ poetry run <command>  # 仮想環境を有効にして実行

.. code-block:: shell

    $ poetry install  # poetry.lockを元に環境再現（+ editable install）

uv（2024〜） [#openai-astral]_
------------------------------------------------------------

.. code-block:: shell

    $ curl -LsSf https://astral.sh/uv/install.sh | sh  # 他miseで入れる。などなど

.. code-block:: shell

    $ uv python install  # Python自体も管理
    $ uv init my-project
    $ cd my-project
    $ uv add 'httpx2>=2.12.0'  # uv.lock 作成
    $ uv run <command>  # 仮想環境を有効にして実行

.. code-block:: shell

    $ uv sync  # uv.lockを元に環境再現。*爆速*

.. [#openai-astral] 開発元のAstralを2026年にOpenAIが買収しています

uv使う上で [#uv-init-change-0-12-0]_ 🏃‍♂️
------------------------------------------------------------

* 生成される :file:`pyproject.toml` も使い倒しましょう。 `[tool.ham] <https://packaging.python.org/ja/latest/guides/writing-pyproject-toml/>`__ に設定書けます！
* ``uv run`` はロックファイル更新とそれに仮想環境の同期が **自動** [#uv-automatic-lock-and-sync]_
* `migrate-to-uv <https://github.com/osprey-oss/migrate-to-uv>`__：Poetryなどからuvへ移行
