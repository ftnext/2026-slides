仮想環境 **人力** 管理
============================================================

.. code-block:: bash

    $ python -m venv .venv --upgrade-deps
    $ source .venv/bin/activate
    (.venv) $ python -m pip install sampleproject

Pythonチュートリアルが人力パッケージ管理を指南
------------------------------------------------------------

.. code-block:: bash
    :caption: `12.3. pip を使ったパッケージ管理 <https://docs.python.org/ja/3/tutorial/venv.html#managing-packages-with-pip>`__

    (.venv) $ python -m pip uninstall sampleproject
    (.venv) $ python -m pip freeze > requirements.txt

チュートリアルの範囲はこれで十分

人力でPythonプロジェクトはしんどくなる
------------------------------------------------------------

inline script metadata
============================================================

チュートリアルでサードパーティライブラリを使ったスクリプトに推す

従来の人力管理
------------------------------------------------------------

.venvとscript.pyを置く

PEP 723 - inline script metadata
------------------------------------------------------------

.. code-block:: python
    :caption: 特殊なコメント

    # /// script
    # requires-python = ">=3.12"
    # dependencies = [
    #   "httpx2",
    # ]
    # ///

inline script metadataをサポートしたツールは
------------------------------------------------------------

1. 指定されたPythonバージョンで仮想環境を作成
2. 指定された依存を仮想環境にインストール
3. その仮想環境でスクリプトを実行

uvとinline script metadata
------------------------------------------------------------

* `uv init --script <https://docs.astral.sh/uv/reference/cli/#uv-init--script>`__
* `uv add --script <https://docs.astral.sh/uv/reference/cli/#uv-add--script>`__
* ``uv run`` にスクリプトを渡す

Pythonスクリプトの持ち運びに超便利
------------------------------------------------------------

Pythonスクリプト開発中は？（デバッグしたい）
------------------------------------------------------------

* ``uv run --with httpx2 python -i script.py``
* ``uv venv``・``uv pip install httpx2``・``.venv/bin/python -i script.py``

.. 2点目はチュートリアルの仮想環境操作と変わらない

小まとめ🥟「venv を作って pip install」の代わりにuv
============================================================

* 仮想環境を理解していなくても使えるinline script metadata（使いたいライブラリが明確な場合に有用）
* Pythonプロジェクトへ進む際も、uvの別のコマンドを知ればよい

.. uv run -> uv add --script -> uv init
