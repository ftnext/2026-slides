Part2 uv登場
============================================================

煩雑な仮想環境管理をツールにやらせる流れが重なり [#tools-history-pyconjp]_ 、uvに至る

.. [#tools-history-pyconjp] 登場した数々のツールについてはPyCon JPのスライドをどうぞ。コマンドの形はPoetryが先駆けです

uv（2024〜）
------------------------------------------------------------

* Astralという会社が提案（`3月にOpenAIが買収 <https://x.com/OpenAINewsroom/status/2034616934671724639>`__）
* 最初はRustで実装された高速なpipとして登場 [#uv-2024-feburary]_
* 0.3.0でPythonプロジェクト管理に機能増強 [#uv-2024-august]_

.. [#uv-2024-feburary] `uv: Python packaging in Rust <https://astral.sh/blog/uv>`__
.. [#uv-2024-august] `uv: Unified Python packaging <https://astral.sh/blog/uv-unified-python-packaging>`__

Astral
------------------------------------------------------------

* Rustのツールチェイン（``rustup`` や ``cargo``）を信奉
* リンタ・フォーマッタ `Ruff <https://github.com/astral-sh/ruff>`__ や、型チェッカ `ty <https://github.com/astral-sh/ty>`__ もAstral製です
* IMO：Python環境構築を圧倒的に簡単にしてくれてありがとう（ただ言いたいことはいっぱいあるけどね）

uvのインストール [#uv-standalone-installer]_
------------------------------------------------------------

.. code-block:: shell
    :caption: macOS/Linux

    $ curl -LsSf https://astral.sh/uv/install.sh | sh

.. code-block:: shell
    :caption: Windows

    > powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

.. code-block:: shell
    :caption: バイナリなので色んなインストール方法

    $ mise use -g uv

.. [#uv-standalone-installer] https://docs.astral.sh/uv/getting-started/installation/#standalone-installer ``uv self update`` も裏でこのシェルを叩きます

uvは **Pythonも管理** できる [#uv-python-commands]_
------------------------------------------------------------

.. code-block:: shell
    :caption: `Installing Python versions <https://docs.astral.sh/uv/guides/install-python/>`__

    $ uv python install 3.15 3.14

* どの環境でも同じコマンド（後述するが省略もできる）
* 複数のPythonを管理するツール（例：pyenv）とも共存しますし、uvに切り替えられます

.. [#uv-python-commands] https://docs.astral.sh/uv/reference/cli/#uv-python

新規プロジェクト作成 [#uv-init-command]_
------------------------------------------------------------

.. code-block:: shell
    :caption: `Creating and working on projects <https://docs.astral.sh/uv/guides/projects/>`__ （後続例も）

    $ uv init my-project
    $ cd my-project

.. code-block:: txt
    :caption: src-layout

    .
    ├── .git/
    ├── .gitignore
    ├── .python-version
    ├── pyproject.toml
    ├── README.md
    └── src/
        └── my_project/
            └── __init__.py

.. [#uv-init-command] https://docs.astral.sh/uv/reference/cli/#uv-init

仮想環境はuvにお任せ：依存の追加
------------------------------------------------------------

.. code-block:: shell
    :caption: venvやpipを扱う必要なし

    $ uv add httpx2 --bounds major

.. code-block:: toml
    :caption: :file:`pyproject.toml` に書かれる

    [project]
    dependencies = [
        "httpx2>=2.16.0,<3.0.0",
    ]

:file:`.venv/` と :file:`uv.lock` も作成される

仮想環境はuvにお任せ：uv経由で有効化
------------------------------------------------------------

.. code-block:: shell
    :caption: 手動で有効化の必要なし

    $ uv run <command>

**uvが仮想環境を有効にして** コマンド実行

uvで管理する既存Pythonプロジェクトは **簡単に立ち上がる**
------------------------------------------------------------

.. code-block:: shell

    $ uv sync  # *爆速* 環境再現

* :file:`uv.lock` の通りに仮想環境も整う
* 必要なPythonがマシンになければインストールされる（:file:`.python-version` や :file:`pyproject.toml`）

uvと仮想環境
------------------------------------------------------------

* venvは使わずに仮想環境（ディレクトリ）を作る [#pep-405]_
* pipはない（uvが担えるので）
* uvコマンドを使う限りは **仮想環境は意識しなくてよくなっている**

.. [#pep-405] `PEP 405 – Python Virtual Environments <https://peps.python.org/pep-0405/>`__

裏の仕組み：python-build-standalone
------------------------------------------------------------

* `CPythonはビルドが必要 <https://docs.python.org/ja/3/using/configure.html>`__ だったが
* https://github.com/astral-sh/python-build-standalone
* **Python処理系をダウンロードしたら動かせる** ようになっている！uvはこれを使っている
